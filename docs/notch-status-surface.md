# Codexling 刘海状态面设计与参考

> 记录日期：2026-08-03
> 当前范围：`/preview` 交互原型；尚未修改 macOS 正式版实现。

## 1. 为什么增加刘海模式

Codexling 状态栏最重要的两类信息是：

1. 本地 Agent 当前任务状态，尤其是等待确认、执行中和失败。
2. 当前登录账号的可用额度，或 API Key 的可用余额。

多账号轮播会带来文案长短差异。如果状态项按内容动态改变宽度，菜单栏里的其他图标会左右移动；在带摄像头刘海的 MacBook 上，可用菜单栏宽度又被分成左右两段，长胶囊更容易与系统状态项冲突。

因此预览先验证两项调整：

- **现有状态栏胶囊固定宽度**：状态与额度可以轮播，但外轮廓不再变化。
- **新增刘海状态面**：把摄像头区域当成不可绘制的中心锚点，收起时信息分布在左右两翼，悬停后向下展开。

## 3. macOS 屏幕几何依据

正式版不能通过机型名单猜测刘海尺寸，应按当前 `NSScreen` 动态计算：

- [`safeAreaInsets`](https://developer.apple.com/documentation/appkit/nsscreen/safeareainsets)：顶部非零时表示内容可能被摄像头外壳遮挡。
- [`auxiliaryTopLeftArea`](https://developer.apple.com/documentation/AppKit/NSScreen/auxiliaryTopLeftArea-uglc)：刘海左侧可用区域。
- [`auxiliaryTopRightArea`](https://developer.apple.com/documentation/AppKit/NSScreen/auxiliaryTopRightArea-gr2n)：刘海右侧可用区域。
- [`visibleFrame`](https://developer.apple.com/documentation/appkit/nsscreen/visibleframe)：普通窗口可安全使用的屏幕区域；它不会包含菜单栏、Dock 和刘海两侧区域。

运行时约束：

1. 每次显示器、分辨率、缩放或菜单栏归属变化后重新读取屏幕几何，不缓存固定值。
2. 有 `auxiliaryTopLeftArea` 和 `auxiliaryTopRightArea` 时启用刘海模式。
3. 无刘海、外接显示器或空间不足时退化为顶部居中固定宽度胶囊。
4. 不覆盖系统菜单栏项目，不假设左右两翼一定有足够宽度。

### 3.1 非刘海屏与外接显示器

同类项目的主流处理不是绘制一个宽大的假刘海，而是使用屏幕顶部居中的 **Floating Pill / Floating Island**：

- Atoll 2.0 为外接屏和无刘海 Mac 增加 Dynamic Island 与自动隐藏。
- Notchy 在检测到无刘海显示器时切换 Floating Pill，并允许选择目标显示器。
- 面向 Coding Agent 的 xisland 在外接屏或旧款 Mac 上使用顶部居中的紧凑悬浮栏。
- 仅面向带刘海 MacBook 的项目（例如 Atoll 早期版本）则会直接把带刘海设备写入系统要求，这种限制不适合 Codexling 的多显示器目标。

Codexling 因此采用三级降级：

1. **刘海状态面**：有物理刘海且左右安全区足够时使用。
2. **顶部悬浮胶囊**：无刘海 Mac 或外接显示器的默认方案；固定宽度，悬停向下展开，空闲时可以自动隐藏。
3. **系统菜单栏胶囊**：用户关闭悬浮层、屏幕顶部空间不足或窗口层级受限时使用。

多显示器默认跟随当前承载系统菜单栏的显示器；设置中应允许选择“跟随菜单栏 / 内建显示器 / 指定显示器 / 所有显示器”。同一时刻只允许一个面板接受点击，避免多屏同时展开。

## 4. Codexling 的交互方案

### 4.1 收起态

- 外轮廓宽度固定，账号切换不改变占位。
- 刘海中央只作为摄像头避让区，不放文字或按钮。
- 左翼显示最高优先级任务状态与状态圆灯。
- 右翼显示当前轮播账号 Logo 与紧凑额度。
- 状态、额度、账号高亮使用同一个轮播索引，避免出现“Kimi 状态 + Codex 额度”的语义错位。

### 4.2 展开态

- 悬停从刘海向下展开；点击后保持展开，再次点击关闭。
- Web 预览暂时使用普通圆角近似刘海轮廓，不再尝试用 CSS 还原反向圆角；正式版 App 必须使用原生路径实现反向圆角，具体要求见第 7 节。刘海收起态与展开态均不显示边缘流光，以保持与物理摄像头区域一致的纯黑轮廓。
- Pet 是任务区视觉锚点，但不占用收起态菜单栏空间。
- 中部显示任务标题、Agent、账号和状态。
- 右侧显示额度或 API Key 余额。
- 底部 Logo 列表用于直接切换账号，左右按钮用于顺序浏览。
- 自动轮播保持可见；未来正式版可提供“悬停暂停”设置，而不是写死行为。

### 4.3 注意力优先级

刘海收起态优先展示：

```text
等待确认 > 失败/中止 > 工作中 > 检查中 > 思考中 > 完成 > 空闲
```

额度状态只改变右翼信息和额度健康色，不应覆盖等待确认等任务告警。API Key 没有本地任务时，左翼显示余额健康状态。

## 5. 尺寸与动效约束

- 现有状态栏胶囊预览宽度固定为 `218px`。
- 刘海收起态预览宽度固定为 `310px`，中央保留 `104px` 摄像头避让区。
- 普通屏降级胶囊固定为 `248px`。
- 展开面板目标宽度 `430px`，窄窗口限制在视口减去安全边距。
- 刘海屏使用纯黑承载面；无刘海屏不绘制黑色悬浮岛，直接回退到最初的系统状态栏胶囊方案。
- Web 预览只表达信息层级、开合状态与降级逻辑，不作为刘海轮廓的像素级验收依据。
- 只保留原始状态栏胶囊自身的活动流光；刘海面板不增加流光。
- 形变只改变宽高和圆角，不让内部文本决定外轮廓尺寸。
- 遵循“减少动态效果”设置时，应取消轮播位移动画，只做即时内容替换。

这些数值仅用于 Web 原型。正式版必须由实际 `NSScreen` 几何、字体测量和菜单栏可用空间共同决定。

## 6. 正式版后续工作

1. 建立 `NotchSurfaceController`，与现有 `StatusBarController` 共用任务和额度 ViewModel。
2. 用 `NSScreen` 的安全区域属性选择刘海模式或普通屏降级模式。
3. 使用不抢焦点的浮层窗口；悬停展开时保留安全三角区，避免鼠标跨越间隙导致闪退。
4. 支持多显示器菜单栏归属变化、全屏 Space、自动隐藏菜单栏和屏幕缩放。
5. 设置中提供：显示位置、自动轮播周期、悬停是否暂停、仅告警时展开。
6. 在真实 14/16 英寸刘海屏、无刘海 MacBook 和外接显示器上分别验证。

## 7. 正式版 App 必做：原生反向圆角

> 这是正式版验收项，不是可选视觉优化。Web 预览已明确放弃用 CSS 近似该形状。

### 7.1 参考与许可

几何逻辑参考 Apache-2.0 项目 [Ping Island 的 `NotchShape.swift`](https://github.com/erha19/ping-island/blob/main/PingIsland/UI/Components/NotchShape.swift)。参考实现使用 SwiftUI `Shape` 与二次贝塞尔曲线构造刘海轮廓；Codexling 应在自己的原生视图中重新实现同等几何能力，并在第三方许可记录中保留来源。

### 7.2 路径要求

原生 `Shape.path(in:)` 必须按以下顺序构造闭合路径：

1. 从面板左上角开始。
2. 使用二次曲线进入向右内收的左侧垂直边。
3. 沿左侧边下行至底部圆角。
4. 绘制左下圆角、底边与右下圆角。
5. 沿右侧边上行。
6. 使用镜像二次曲线回到右上角。
7. 沿屏幕顶边闭合路径。

关键点是：顶部横边完整贴住屏幕，垂直侧边相对顶部连接点向内偏移；它不是普通 `RoundedRectangle` 的凸圆角，也不是“窄连接颈 + 主面板”。

### 7.3 状态参数

| 状态 | 顶部反向圆角 | 底部圆角 | 说明 |
|---|---:|---:|---|
| 收起 | `6pt` | `14pt` | 轻微内收，左右信息翼仍保持紧凑 |
| 展开 | `19pt` | `24pt` | 与大面板宽度匹配，形成清晰的屏幕衔接肩部 |

圆角值应参与 `animatableData`，开合动画中从收起参数连续插值到展开参数，不能在状态切换时突然换路径。

### 7.4 尺寸与适配

- 路径必须基于运行时 `rect` 计算，禁止写死 310px 或 430px 坐标。
- 面板宽高变化时，左右曲线保持镜像，底部圆角不得超过可用高度。
- 根据 `NSScreen.safeAreaInsets` 和左右辅助区域确定物理刘海宽度。
- 无刘海屏不使用该 Shape，直接回退到现有状态栏胶囊。
- 内容布局必须避开顶部内凹区域，文字和按钮不能进入曲线裁切范围。

### 7.5 验收清单

- 收起态左右两处都能看到连续、无折线的反向圆角。
- 展开态顶部与屏幕边缘无方角、白缝或透明断层。
- 从收起到展开的曲线连续变形，没有轮廓跳变。
- 14 英寸、16 英寸刘海屏和不同缩放比例下左右对称。
- 菜单栏自动隐藏、全屏 Space 与多显示器切换后重新计算路径。
- 刘海面板无边缘流光；无刘海回退胶囊保留原有流光。
